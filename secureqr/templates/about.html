About SecureQR

QR codes hide their destination until you open them. That makes them a convenient lure for phishing ("quishing"): a sticker over a parking-meter code, a fake payment QR at a shop counter, a "verify your account" code in an e-mail that slips past link filters. SecureQR shows you what a code contains and how risky it looks before you act on it.

How a scan works

  1. Validation. Uploads are checked for size, extension, file signature and pixel count, then decoded in memory. Nothing is written to disk.
  2. Decoding. OpenCV's QR detectors run on the image and, if needed, on enhanced versions (colour-channel thresholding and erosion) that recover stylised and dotted codes{% if 'pyzbar' in backends %}; pyzbar is also installed and runs first{% endif %}.
  3. Content type. The payload is classified: web link, UPI payment, Wi-Fi, phone, SMS, e-mail, contact or text. Only links go to the model.
  4. Machine learning. A Linear SVM scores the link from character 3–5-gram TF-IDF features and 30 hand-crafted lexical features. Probabilities come from sigmoid calibration.
  5. Security rules. Independent checks look for raw IP hosts, shorteners, '@' tricks, punycode, brand names outside the real domain, risky TLDs, dangerous schemes, executable downloads, redirects and missing HTTPS.
  6. Risk level. High if a critical rule fires, the rule score is 50 or more, or the model is at least 80% sure and a rule agrees. Medium if either signal is moderate. Low otherwise.

What it will not do

  • It never opens, fetches or resolves a scanned link, so a scan cannot trigger a download, tip off an attacker, or be abused to reach internal servers.
  • It does not know where a shortened link really leads. Treat shortened links with extra care.
  • It cannot see the page behind a link, so a brand-new phishing site on a clean-looking domain can still score low.

Privacy and security

  • Scan history lives in a local SQLite database and can be cleared from the History page.
  • Webcam video never leaves your browser except as single still frames sent to this server for decoding; frames are not stored.
  • CSRF tokens on every state-changing request, per-IP rate limits, a strict Content Security Policy, parameterised SQL and auto-escaped output.
